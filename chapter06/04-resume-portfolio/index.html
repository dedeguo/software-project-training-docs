    6.4 整理简历：项目描述与面试表达¶

    让课程项目成为求职或毕业设计的有效资产¶

    简历项目不是罗列功能，而是证明你能用技术解决真实问题

    6.3 完成个人贡献说明后，你已经知道自己做了什么。但简历和面试需要更进一步：用简练的语言，在 2—3 条项目描述中展示技术能力、解决问题能力和成果验证能力。

    本节将帮助你将项目成果转化为简历项目描述、作品集链接和面试表达，确保成果可复用于求职、毕业设计或继续学习。

    编写 2—3 条简历项目描述，使用 STAR 法则；整理作品集链接清单，包含 GitHub、演示视频和文档；准备 30 秒、2 分钟和 5 分钟三个版本的面试表达；列出 10—15 个常见面试问题与回答要点。

    一、简历项目描述：用 STAR 法则展示能力¶

    1. STAR 法则¶

    STAR 法则是结构化回答面试问题的方法，也适用于简历项目描述。

    要素 含义 示例
    Situation（背景） 项目背景、解决的问题 校园失物信息分散，认领过程难追踪
    Task（任务） 你的职责、目标 负责后端开发，实现用户认证和失物管理
    Action（行动） 你做了什么、怎么做的 设计 JWT 鉴权和角色权限控制，编写 15 个测试用例
    Result（结果） 成果、量化指标 3 个 P0 缺陷全部修复，Docker 一键部署成功

    【项目背景 30s】
我开发了一个校园失物招领平台，解决校园失物信息分散、认领过程难追踪、虚假认领难审核的问题。

【需求分析 60s】
项目支持三类角色：失主、拾到者和管理员。核心功能包括失物发布、关键词搜索、认领申请、
管理员审核和归还确认。业务规则包括：同一用户不能重复认领、认领需管理员审核、归还后状态不可修改。

【技术选型 60s】
后端选择 Spring Boot 3 和 MyBatis-Plus，原因是生态成熟、适合企业级应用、团队有 Java 基础。
前端选择 Vue 3 和 Pinia，原因是学习曲线平缓、组合式 API 便于代码组织。
数据库选择 MySQL 8，原因是开源免费、社区活跃、适合中小型项目。
部署选择 Docker Compose，原因是降低部署门槛、确保可复现。

【架构设计 60s】
采用前后端分离架构，前端通过 Nginx 代理 /api 访问后端。后端分为 controller、service、dao 三层，
通过 DTO 和 VO 隔离内部模型和外部接口。鉴权使用 JWT + 拦截器，通过注解控制角色权限。
数据库设计包含用户、失物、认领、审核四张核心表，通过外键关联确保数据一致性。

【难点解决 60s】
遇到三个主要问题：
1. 重复认领：服务层未判断用户是否已有认领记录，通过新增唯一查询和业务异常解决。
2. 权限绕过：删除接口未校验用户角色，通过新增角色权限注解和拦截器校验解决。
3. Docker 部署：后端容器连不上数据库，通过将 DB_HOST 从 localhost 改为服务名 mysql 解决。

【测试验证 30s】
编写 15 个测试用例，覆盖正常、异常和权限场景，发现并修复 3 个 P0 缺陷，全部回归通过。
在 Docker 环境完成核心流程验证，系统运行稳定。

【总结 30s】
通过这个项目，我掌握了 Spring Boot 和 Vue 的全栈开发能力，学会了 Docker 容器化部署，
理解了测试驱动开发的重要性。项目代码在 GitHub，有完整的文档和测试报告。

    四、常见面试问题与回答要点¶

    1. 技术类问题¶

    问题 回答要点
    为什么选择 Spring Boot？ 生态成熟、依赖注入、AOP、自动配置
    JWT 和 Session 的区别？ 无状态、可扩展、适合前后端分离
    MyBatis-Plus 的优势？ 代码生成、分页插件、乐观锁、逻辑删除
    Docker 的优势？ 环境隔离、可复现、快速部署
    Vue 3 的组合式 API 有什么优势？ 逻辑复用、类型推导、代码组织

    2. 项目类问题¶

    问题 回答要点
    项目最大的难点是什么？ 具体问题、根因分析、解决过程、验证结果
    你在项目中负责什么？ 具体模块、关键决策、量化成果
    项目的测试覆盖率是多少？ 核心功能 100%、异常 80%、权限 100%
    项目部署在哪里？ Docker 本地部署、局域网访问、可复现
    项目有多少用户？ 课程项目，测试数据 10 条，未上线

    3. 个人类问题¶

    问题 回答要点
    你从这个项目中学到了什么？ 技术能力、工程能力、协作能力、反思能力
    你觉得项目有什么不足？ 诚实承认、说明原因、后续改进计划
    如果重新做，会怎么改进？ 测试驱动开发、CI/CD、监控日志
    你如何学习新技术？ 官方文档、视频教程、实践项目、社区交流
    你的职业规划是什么？ 短期目标、中期目标、长期目标

    五、面试表达的注意事项¶

    1. 回答技巧¶

    • STAR 法则：用背景 → 任务 → 行动 → 结果组织回答；
    • 具体而非模糊：用具体例子代替空泛描述；
    • 量化而非定性：用数字说明成果；
    • 诚实而非虚构：不知道的问题诚实说明；
    • 简洁而非冗长：控制回答时间，突出重点。

    2. 常见错误¶

    错误 正确做法
    夸大技术栈 只写实际使用的技术
    虚构职责 明确个人贡献和团队贡献
    抄袭简历 基于真实项目经历编写
    无证据支持 提供 GitHub 仓库、演示视频
    回答过长 控制时间，突出重点

    3. 面试前的准备¶

    • 简历项目描述已更新，使用 STAR 法则；
    • 作品集链接已验证可访问；
    • 30 秒、2 分钟、5 分钟三个版本的面试表达已练习；
    • 10—15 个常见面试问题已准备回答要点；
    • 已准备现场演示方案（如需要）；
    • 已准备备用方案（如网络中断）。

    六、提交前自查¶

    • 简历项目描述 2—3 条，使用 STAR 法则，具体、可验证；
    • 作品集链接清单包含 GitHub、演示视频、文档链接；
    • 所有链接已验证可访问；
    • 面试表达脚本 30 秒、2 分钟、5 分钟三个版本已准备；
    • 常见面试问题 10—15 条，每条有回答要点；
    • 简历描述与实际项目一致，无虚构内容；
    • 已进行至少一次模拟面试，时间控制和回答质量符合预期。

    本节小结¶

    整理简历的核心是证明你能用技术解决真实问题，并且能把过程和结果讲清楚：

    简历项目描述用 STAR 法则 → 作品集让成果可访问 → 面试表达准备三个版本 → 常见问题准备回答要点。

    完成本节后，你将拥有可复用于求职、毕业设计或继续学习的项目资产。下一节将帮助你完成项目复盘，识别经验、差距和后续行动计划。
