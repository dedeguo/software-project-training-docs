# 系统 UI 原型交付指南

## 设计依据与工具选择

以完成的《系统设计说明书》为依据，沿用其中的页面编号、角色、字段、操作、业务状态和关键反馈。需求阶段的低保真原型用于核对入口和页面流程。尚未确认的设计标明待确认，避免把临时假设写成既定规则。

1. 默认用 HTML、CSS 和原生 JavaScript 在项目目录交付本地原型。只需当前工具能读取设计材料并写入项目文件，学生用普通浏览器即可打开。
2. 开始前可检查当前客户端已有的 UI 设计、原型或浏览器预览能力。已启用且适合当前任务时，可用于布局探索、制作或核验。安装方式、连接权限及可用功能以该客户端实际环境为准。使用外部设计画布或发布原型须遵循用户授权。
3. 当前客户端无法自动加载技能时，让它直接读取本技能的 `SKILL.md` 和本指南。辅助工具输出设计稿、预览链接或框架代码时，仍按本指南整理成可独立打开的 HTML。浏览器核验可由学生手动完成。

## 原型内容

- 从页面清单中选择支撑必做业务的核心页面。按角色提供明确入口，至少完整串起一条主流程，标明各页面对应的说明书编号。
- 使用贴近业务的模拟数据和一致的视觉层级。为核心按钮、表单、筛选或切换实现演示所需的交互，并按说明书展示处理前后的状态和提示。
- 演示至少两个与核心规则相关的异常或边界状态，例如名额已满、权限不足、重复提交或数据为空。只选与本题相关的场景。
- 界面标注「UI 原型 · 模拟数据」。角色切换、状态变化和校验均为浏览器端演示。使用虚构样例，不接入真实账号、数据库或第三方服务。

## 文件与核验

默认交付 `ui-prototype/index.html`。简单项目可将样式、脚本内嵌到单个 HTML；多页面或复杂原型可拆分为同目录下的文件，使用相对路径。成品应能直接用浏览器打开，无需安装依赖、构建或连接后端，演示所需资源随文件交付。

交付前在浏览器打开入口，按角色走通主流程与异常路径，核对跳转、表单反馈、状态显示和页面编号。检查主要视口下的可读性、键盘可操作性与控制台错误。浏览器验证不可用时，检查文件、资源引用和交互代码，并说明未完成的验证。

在说明书中补充原型入口和主要页面对应关系。交付时提供 HTML 入口、打开方式，以及可演示的流程和状态。
