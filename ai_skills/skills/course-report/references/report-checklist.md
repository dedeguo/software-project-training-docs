# 课程报告提交前检查清单

## 使用方式

按“符合 / 不符合 / 待补证据 / 不适用”逐项记录，不默认全部通过。不适用应说明原因。检查通过仅代表已检查范围，不替代学生确认、教师评阅或运行验收。

## 一、依据与范围

- [ ] 已读取学校或教师要求；不存在模板时明确使用通用初稿。
- [ ] 任务书与报告正文均已覆盖本次用户要求的范围。
- [ ] 报告对应的代码、数据库、截图和测试版本已明确。
- [ ] 已区分批准需求、设计方案、实际实现与验证结果。
- [ ] 缺失与冲突集中列出，没有用 AI 推测补成事实。

## 二、任务书

- [ ] 包含主要内容、基本要求和参考资料，或符合学校指定结构。
- [ ] 项目、角色、功能和规则来自该项目，不是照搬示例。
- [ ] 数据编号、长度、唯一性与示例值没有自相矛盾。
- [ ] 要求可检查，必做与选做区分明确。
- [ ] 教师正式要求未被擅自删除、降低或改为当前完成范围。
- [ ] 补整理稿或新编稿明确标注待教师确认，没有倒填下达日期。
- [ ] 教师签名、批准意见和参考资料均未伪造。

## 三、正文内容

- [ ] 摘要与正文一致，没有夸大创新、性能或完成程度。
- [ ] 项目背景有具体场景，无虚构调研、访谈或统计数据。
- [ ] 需求说明角色、流程、规则、范围和验收条件。
- [ ] 架构和技术版本与实际工程一致，选型理由具体。
- [ ] UI 原型与运行截图明确区分，差异有说明。
- [ ] E-R 图、物理表、代码实体与数据库约束已核对。
- [ ] 核心实现能说明页面、请求处理、业务规则与数据变化。
- [ ] 关键代码来自实际项目，位置可追踪；伪代码已明确标注。
- [ ] 正文以必要解释连接图表，而非堆砌截图、代码或技术百科。
- [ ] 部署、本地运行和未验证的操作没有混为一谈。
- [ ] 总结列出任务完成情况、具体收获、未完成项和改进方向。

## 四、测试与证据

- [ ] 每项核心要求可追踪到实现与相应测试，缺项如实披露。
- [ ] 用例有条件、步骤、预期、实际结果、状态及执行证据。
- [ ] 正常、边界、异常、权限和业务状态等适用场景已考虑。
- [ ] 未执行项未写为通过，阻塞项与失败项未被隐去。
- [ ] 总用例、已执行、通过、未通过、阻塞与未执行统计一致。
- [ ] 通过率注明分母与阻塞口径，零分母未计算。
- [ ] 缺陷关闭有回归记录，未关闭问题及影响明确。
- [ ] 构建成功、静态检查、功能测试和专项测试结论未混用。
- [ ] 没有测试证据的性能、安全或兼容性结论已删除或降为待验证。
- [ ] 截图为真实运行材料，未用生成图片或原型冒充。

## 五、一致性、引用与诚信

- [ ] 项目名称、角色、模块、字段、状态、接口名称前后一致。
- [ ] 任务书与实现差异有说明；范围变更有真实依据或待确认标记。
- [ ] 图表编号、图题表题、正文引用、附录和链接对应正确。
- [ ] Mermaid 等图源已渲染或明确标为待导出，不冒充成品图。
- [ ] 参考文献真实，正文引用对应，作者、年份、版本和 URL 已核实。
- [ ] 未泄露真实凭据、个人敏感信息或未脱敏测试数据。
- [ ] 个人贡献有记录支持，不将提交数直接写成贡献百分比。
- [ ] AI 使用说明符合课程要求，人工决策与验证责任明确。
- [ ] 无虚构教师评价、成绩、签名、审批、日期或最终通过结论。

## 六、文件与排版

- [ ] 文件为用户要求的实际格式，不是只更改扩展名。
- [ ] 原始模板未被未经授权覆盖。
- [ ] 自动目录、标题层级、页码和交叉引用在最终排版后已核对。
- [ ] 图片清晰、比例正常，表格无明显截断，附件能够访问。
- [ ] 所有占位和填写提示已处理；仍缺失时保持草稿状态并告知用户。
- [ ] 仅声明实际完成的检查，未预览或未运行的部分明确说明。
