# 课程设计任务书通用模板

## 使用说明

- 本模板沿用“主要内容、基本要求、参考资料”三部分，不是学校正式格式。
- 有教师正式任务书时以其为准，不重写要求来掩盖未完成事项。
- 新整理的任务书须标为草稿、待教师确认。下达时间、签名、审批意见均由有权人员填写，不根据项目完成时间倒推。
- 方括号内容为填写提示，不是可直接提交的事实。

# 课程设计任务书

## 一、主要内容

【项目面向什么业务场景，当前存在什么具体问题，主要由哪些角色使用。说明主要业务对象及其关系，不写无依据的调研结论。】

【角色】可以【关键操作】；【其他角色】可以【相应操作】。核心业务流程为【起点 → 处理 → 结果】。主要数据对象包括【对象清单】，具体表结构由系统设计确定。

系统应完成以下功能：

（1）【功能名称】：【操作角色、操作内容、结果与权限边界】。

（2）【功能名称】：【输入、关键业务规则、成功结果】。

（3）【核心业务功能】：【主要处理环节及状态变化】。

（4）【查询或统计功能，如适用】：【查询条件、数据范围和结果】。

【按批准范围增删条目。选做功能单独标为选做，不能混入必做项。不要机械套用用户管理、角色分级、导出等功能。】

## 二、基本要求

（1）技术与环境要求：【教师指定或已批准的技术路线、数据库和运行条件；无指定则不凭空设限】。

（2）数据要求：【实际相关的持久化、唯一性、必填、取值范围及关联一致性规则】。

（3）业务规则与权限：【核心规则、操作权限、数据权限和非法操作的处理要求】。

（4）界面与交互：【核心流程可完成、操作反馈明确、输入校验等可检查要求；仅在有依据时加入适配要求】。

（5）测试要求：【核心流程、边界和异常、权限等适用场景；应保存实际执行与缺陷回归记录】。

（6）交付要求：【按课程要求列出源代码、数据库脚本、运行说明、课程设计报告、测试材料等，不自行新增强制成果】。

（7）其他课程规定：【教师明确要求的独立完成、组队、AI 使用披露等；无要求则删除此项】。

【以上为写作维度，不是全体项目的统一硬性要求。每条应能找到批准依据或等待教师确认。完成情况写入报告，不能将本节改成“已完成”总结。】
