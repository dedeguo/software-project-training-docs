# 阶段测试执行指南

使用独立测试环境和可重复初始化的模拟数据。核对数据库与外部服务指向，避免测试操作修改真实业务数据。每条用例关联本阶段需求、业务规则或验收条件。

## 单元测试

使用项目既有测试框架验证业务规则、计算、校验、状态转换和异常分支。对需要隔离的外部依赖使用可控替身，核对返回结果及失败后的状态。运行本阶段用例和受影响的既有测试，记录命令、结果和失败详情。

## 接口测试

启动测试环境，向实际服务入口发送请求。验证状态码、响应结构、权限、业务结果与必要的数据读回。按本阶段规则覆盖合法操作、越权、无效输入、非法状态或重复请求。涉及并发、事务和失败恢复时，验证失败操作后的数据一致性。

## 浏览器界面测试

1. 启动本阶段实际实现的系统，准备测试账号和数据。以 UI 原型和页面规格核对页面，验收在运行中的系统上执行。
2. 先检查当前客户端可用的浏览器控制或已有端到端测试工具。可用时实际操作浏览器完成登录、跳转、填写、提交、跨角色确认或刷新后的读回等适用步骤。优先复用项目已有测试工具。
3. 验证主流程和相关异常的页面反馈。记录实际操作、预期状态、观察结果和浏览器环境。失败时保存可取得的截图、报错或复现步骤。自动化用例可保留脚本或运行报告。
4. 浏览器控制不可用时，给出可逐步执行的人工复测清单。学生实际执行并提供结果后，标记为人工测试并记录证据。在收到结果前将该项标为阻塞或未执行。接口响应、静态代码检查和原型预览各自记录为对应检查。

## 阶段回归

修复缺陷后重跑失败用例及受影响的既有用例。阶段之间检查共享接口、权限规则和数据迁移是否影响已验收流程。最终回归从可复现的初始化状态运行，并保留关键主流程与异常流程的实测记录。
