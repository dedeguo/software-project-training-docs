# 《软件开发综合项目实训》课程脚手架设计方案

> 课程脚手架设计讨论的归档文档，配套电子教程第四篇「项目开发与业务实现」使用。

## 一、目标定位

解决学生启动项目时的三大痛点：

- **不知道用什么结构** —— 提供规范的分层目录
- **基础设施不会写** —— 提供通用的登录 / 异常 / 响应 / 配置
- **AI 协作没有约束** —— 内置 `AGENTS.md`、`.trae/skills/.keep`、课程 Skill

## 二、技术栈

| 层 | 技术 |
| :--- | :--- |
| 后端 | JDK 17、Spring Boot 3.x、Maven、MyBatis-Plus |
| 数据库 | MySQL 8（兼容说明 openGauss） |
| 鉴权 | JWT + 拦截器 |
| 前端 | Vue 3 + Vite + Pinia + Vue Router + Axios |
| 部署 | Dockerfile + docker-compose + Nginx |
| 工具链 | Git、Apifox、Trae、AGENTS.md |

## 四、必跑通的最小闭环

预置 1 个**完整可登录 + 1 个 CRUD** 示例（命名 `module-demo`，可改造为书 / 商品 / 失物等）：

- **登录**：`POST /api/auth/login` 返回 JWT，前端存 Pinia + localStorage
- **分页列表**：`GET /api/demo-items?page=&size=` 返回 `ApiResponse<PageVO<ItemVO>>`
- **CRUD**：新增、修改、删除、详情
- **权限演示**：管理员可见 `module-admin`，普通用户可见 `module-demo`
- **错误演示**：触发业务异常 → `GlobalExceptionHandler` → 标准 JSON 响应

学生拿到脚手架后：

1. 第一步改名 + 换业务表 → 变为自己项目；
2. 第二步再增加特色功能。

## 六、学生使用流程

对应电子教程第四篇章节：

1. **下载脚手架**：GitHub 仓库「Use this template」或 `git clone`
2. **运行体验**：`docker-compose up` → 浏览器看到登录页
3. **看文档**：`AGENTS.md` + `README.md` 理解结构与规则
4. **改造工程**：改名 `module-demo`、换表、删掉示例数据
5. **跑通业务**：实现自己的第一个模块
6. **AI 协作**：通过 `.trae/skills/` 调用 `system-design` 等课程 Skill
7. **测试部署**：单测 + Apifox + Docker 部署

## 八、实施 checklist

**后端基础设施（必做）**

- 统一响应 `ApiResponse<T>` + 分页 `PageVO`
- 业务异常 `BusinessException` + `GlobalExceptionHandler`
- JWT 工具 + 拦截器 + 注解 `@RequireRole`
- CORS 配置
- 多环境 `application-{dev,prod}.yml`
- Flyway 初始化脚本

**后端业务（必做）**

- `auth` 模块：注册 / 登录 / 获取当前用户
- `demo-item` 模块：分页 + CRUD

**前端基础设施（必做）**

- Axios 封装（拦截器、Token 注入、统一错误提示）
- 路由守卫（未登录跳登录）
- Pinia user store
- 通用组件：Pagination、Empty、Loading
- 两种布局：DefaultLayout、AdminLayout

**前端业务（必做）**

- 登录页、注册页
- 列表 + 表单（CRUD 完整页面）

**AI 协作（必做）**

- `AGENTS.md`（技术栈、目录约定、改动禁区）
- `.trae/skills/.keep` + 安装说明
- `.trae/rules/*.md`（项目级规则）

**配套（必做）**

- `README.md`（5 分钟上手）
- Postman 接口集
- `docs/` 4 份过程文档模板（需求 / 设计 / 测试 / 项目说明）
- `Dockerfile`（后端、前端）
- `docker-compose.yml`
- `deploy/nginx/default.conf`
- `LICENSE`
- `.gitignore`

### 多版本脚手架的技术栈选择

课程提供两份姊妹脚手架方案，学生根据自身基础选择其一或对照学习：

| 路线 | 适用学生 | 仓库 | 方案文档 |
| :--- | :--- | :--- | :--- |
| 主流路线 | 已学 Java 基础、想掌握主流框架、就业导向 | `scaffold-springboot` | 本文档 |
| 入门路线 | 基础课刚结束、希望先夯实 Servlet / Filter / JDBC 原理 | `scaffold-servlet` | [Servlet 版方案](《软件开发综合项目实训》课程脚手架设计方案（Servlet版）.md) |

两版的最小闭环一致（登录 + CRUD），便于学生跨版本对照学习，详见 [Servlet 版方案的"十二、与 Spring Boot 版的对照表"](《软件开发综合项目实训》课程脚手架设计方案（Servlet版）.md#十二与-spring-boot-版的对照表教学选用参考)。

## 十一、关键决策点

| 议题 | 结论 |
| :--- | :--- |
| MyBatis-Plus vs MyBatis | 课程降低样板代码，倾向 MP；保留 XML 用法教学点 |
| JWT vs Session | 前端 Vue 选 JWT 拦截器；`book-manage` 的 Filter 模式保留为对照示例 |
| MySQL vs openGauss | 主推 MySQL；`sql/init.sql` 标出兼容差异（`AUTO_INCREMENT` / `SERIAL`） |
| 单测范围 | 仅给一个 controller / service 单测示例，避免学生负担 |
| Docker | `docker-compose.yml` 编排 mysql + backend + frontend + nginx，作为进阶演示 |
| 仓库命名 | `scaffold-springboot`（Gitee 仓库已创建：<https://gitee.com/javaweb-dev-tech/scaffold-springboot>） |
| 仓库位置 | 与 `software-project-training-docs` 平级的独立 Gitee 仓库（组织 `javaweb-dev-tech`） |
