# 《软件开发综合项目实训》第一课 PPT 大纲

> 课程：软件开发综合项目实训 ｜ 学时：64（16 周 × 4 学时）｜ 工具：Trae + 课程 Skills 技能包
>
> 篇幅：31 页，讲授约 90 分钟，余下时间用于学生现场实操

---

## 总体设计说明

- **风格**：封面用"学生完成的作品截图"开场（图书管理系统界面），先看见成果，再讲规则
- **主线**：贯穿全课一句话——"选一个愿意做的项目 → 每节课完成一个小任务 → 每周看到项目进展 → 最终交付一件完整作品"
- **每页布局**：标题 + 3~5 条要点 + 一张配图/表格，避免整页文字

---

## 一、课程概述（第 1~6 页）

### P1 封面页

- 课程名称《软件开发综合项目实训 —— AI 辅助的软件项目开发》
- 授课教师、开课时间、课时信息
- 副标题：用 AI 完成一件属于你自己的软件作品

### P2 课程定位与背景

- 软件开发方式正在被 AI 改变：从"背语法写代码"到"人机协作开发"
- 传统课堂 vs 本课程对比（做菜比喻）：照着炒一盘 vs 自己做一道拿手菜
- 本课是一门"AI 辅助软件工程综合实践课"，而非纯理论课或纯编码课

### P3 为什么开设这门课（背景与意义）

- 企业用人需求变化：AI 编程工具已成为开发日常，会"驾驭 AI 完成项目"是核心能力
- 面向应用型人才培养：综合运用程序设计、Java Web、数据库、前端与软件工程知识
- 一句话：培养**能够驾驭 AI 完成软件项目**，而不是只会复制 AI 代码的开发人才

### P4 课程整体结构介绍

- 三条主线贯穿：项目实战、AI 工具、文档规范
- 三篇递进结构：
  - 第一篇 AI 协同开发实战（图书管理系统带练，先跑通一个闭环）
  - 第二篇 项目选题与需求分析（立项书、需求分析说明书）
  - 第三篇 原型与系统设计（架构图、原型、E-R 图、设计说明书）
- 六阶段流程：选题 → 需求 → 设计 → 开发 → 测试部署 → 答辩展示

### P5 学习本课程的预期收获（学生能带走什么）

- 一个可运行、可部署、可演示的完整软件项目
- 一套"先读文档、再拆任务、边做边验证"的 AI 协作方法
- 完整的项目过程文档（选题立项书、需求、设计、测试报告）
- 课程成果可直接转化为：毕业设计基础、竞赛作品、求职项目经历

### P6 第一课目标预告

- 今天你能带走：认识课程全貌 + 注册并上手 Trae + 完成一次 AI 编程初体验

## 二、课程目标（第 7~9 页）

### P7 三大目标总览（一图总览）

- 项目实践目标 / 知识储备目标 / 职业发展目标
- 图示：三个目标指向同一个交付物——"一件能运行、能讲清、能展示的作品"

### P8 项目实践目标

- 独立完成课程指定项目开发（原则上个人独立完成，组队不超过 3 人且需审核）
- 经历完整流程：选题、需求、设计、编码、测试、部署、答辩
- 达成标准：项目能运行、业务闭环完整、能解释自己的代码

### P9 知识储备与职业发展目标

- 知识储备：为毕业设计奠定技术基础（需求分析、系统设计、工程化开发方法）
- 职业发展：培养符合企业需求的实习就业技能
  - 与 AI 协作开发的能力
  - 审查、调试、验证 AI 生成代码的能力
  - Git 版本管理、接口测试、部署交付等工程素养

## 三、课程内容安排（第 10~14 页）

### P10 课程内容总览

- 五块内容：项目开发实践 / AI 工具应用 / 辅助技能训练 / 全流程开发 / 文档撰写
- 内容与"三篇结构、六阶段流程"的对应关系

### P11 项目开发实践

- 基于设计文档，使用 AI 编程工具 Trae 开发**校园图书管理系统**（第一课带练项目）
- 掌握完整开发流程：读文档 → 拆任务 → 开发 → 测试 → 部署
- 课程结束后，学生从真实问题出发自主选题，完成自己的项目
- 展示图书管理系统截图（用户端 + 管理端）

### P12 AI 工具应用

- 详细介绍 Trae：功能特性（对话式编程、代码生成、上下文理解、Agent 协作）
- 使用方法：明确任务 → 提供上下文 → AI 提方案 → 人工审核 → 分步实现 → 验证
- 使用边界：AI 是协作助手，不是代写者；生成内容必须阅读、运行、测试和修改

### P13 辅助技能训练（课程 Skills）

- 认识课程配套技能包：`npx @dedeguo/software-project-training-skills`
- 五大 Skill 分工：
  - `topic-selection` 选题引导
  - `requirements-analysis` 需求分析
  - `requirements-review` 需求评审
  - `system-design` 系统设计
  - `system-design-review` 设计评审
- 作用：用 AI 技能辅助完成项目选题、需求分析与系统设计，AI 不虚构事实，学生负最终责任

### P14 全流程开发与文档撰写

- 全流程开发：使用 Trae 完成编码、测试、部署各阶段工作
- 文档撰写：答辩文档规范（项目说明、测试报告、README、答辩 PPT）
- 强调"文档与项目一致"：需求、设计、代码、测试必须相互对应

## 四、考核要求（第 15~18 页）

### P15 考核构成总览（饼图）

- 六大项占比：

| 考核内容 | 建议比例 | 评价重点 |
| :--- | :---: | :--- |
| 阶段任务与过程验收 | 30% | 每周成果、进度真实性和持续改进 |
| 需求、设计和测试文档 | 15% | 文档是否与实际项目一致 |
| 项目功能与业务闭环 | 20% | 系统是否运行，业务流程是否完整 |
| AI 协作与问题解决 | 15% | 能否审查、修改、调试和验证 AI 输出 |
| 部署、展示与答辩 | 15% | 能否完成交付、演示和解释项目 |
| 团队协作与个人贡献 | 5% | 任务分工、Git 记录和个人真实贡献 |

- 强调：**过程成绩高于一次答辩**，鼓励持续投入，避免期末临时生成

### P16 平时表现评估标准

- 出勤与课堂实践参与度
- 每周成果提交：Git 提交记录、阶段任务卡、项目周报
- 进度真实性、持续改进情况

### P17 项目开发进度考核节点（时间轴）

- 5 个关键验收节点：

| 节点 | 周次 | 阶段成果 |
| :---: | :---: | :--- |
| 立项 | 第 2 周 | 项目立项书 |
| 设计 | 第 4 周 | 需求与系统设计文档 |
| 项目启动 | 第 6 周 | 可运行项目骨架 |
| 中期演示 | 第 11 周 | 可演示的业务闭环 |
| 最终答辩 | 第 16 周 | 最终作品与个人总结 |

### P18 成果评价与答辩评分细则

- 成果评价指标：能否运行、业务闭环是否完整、功能与文档是否一致、AI 使用是否规范
- 答辩评分要点：项目背景与方案讲解 / 系统演示 / 核心代码解释 / 本人真实贡献说明 / AI 参与过程记录
- 明确红线：不能运行、不能解释、无法说明来源的功能，不认定为有效成果

## 五、AI 编程工具初体验（第 19~24 页）⭐ 本课重点实操板块

### P19 Trae 工具介绍

- Trae 是什么：AI 原生 IDE，集成对话式编程与智能代码生成
- 核心特性：AI 对话、代码生成与补全、项目上下文理解、Bug 诊断与修复
- 与其他工具（Git、Apifox、MySQL）在课程中的分工

### P20 注册与环境配置（现场演示）

- 下载安装 Trae → 注册/登录账号
- 检查基础环境：JDK 17、Maven、Node.js、MySQL（版本检查命令）
- 配置课程 AI 规则与 Skills：`npx @dedeguo/software-project-training-skills`
- 现场演示：项目根目录执行安装命令，确认 `.trae/skills/` 生成

### P21 基础功能演示（现场演示）

- 新建/打开项目 → 在对话窗口向 AI 提问
- 生成代码、修改代码、解释代码三类典型操作演示
- 演示"明确任务 → 提供上下文 → 审核方案 → 分步实现"的协作流程

### P22 简单案例实操练习（学生动手）

- 任务：用 Trae 让系统跑起来——克隆图书管理系统模板，启动并登录
- 步骤：导入模板 → 阅读需求/设计文档 → 配置数据库 → 启动项目 → 浏览器验证
- 验收：完成"登录 → 查询图书 → 借阅/归还"其中一条流程即可

### P23 常见问题及解决方法

- 环境类：JDK/Node 版本不匹配、MySQL 连不上
- 启动类：端口占用、依赖下载失败、Tomcat 部署报错
- AI 类：AI 方案不符 → 补充上下文/项目文档；代码报错 → 提供完整日志
- 原则：遇到问题先记录"复现步骤 + 预期 + 实际 + 日志"，再求助

### P24 课堂任务布置（小结）

- 本课必做：完成 Trae 安装与 Skills 配置，启动图书管理系统
- 课后任务：体验系统、熟悉角色与业务，阅读需求分析说明书
- 下节课预告：AI 工具进阶与 AI 协作规则

## 六、课程安排与学习建议（第 25~28 页）

### P25 课程时间规划表（16 周总览）

| 阶段 | 周次 | 核心任务 | 阶段成果 |
| :---: | :---: | :--- | :--- |
| 项目启动 | 1–2 周 | 课程导入、AI 体验、选题审核 | 项目立项书 |
| 需求与设计 | 3–4 周 | 用户分析、功能清单、原型与数据库设计 | 需求与系统设计文档 |
| 项目搭建 | 5–6 周 | 开发环境、Git 仓库、项目骨架 | 可运行项目骨架 |
| 核心开发 | 7–11 周 | 核心模块、角色权限、业务状态流转 | 可演示的业务闭环 |
| 完善交付 | 12–15 周 | 特色功能、测试修复、部署上线 | 可访问的完整项目 |
| 展示评价 | 16 周 | 项目路演、个人答辩、课程复盘 | 最终作品与个人总结 |

- 每节课节奏：20% 讲解 + 30% 示范拆解 + 50% 项目实践

### P26 学习资源推荐

- 在线电子教程：课程网站（三篇教材 + 模板）
- 模板仓库：图书管理系统模板、项目脚手架
- 文档模板：立项书、需求、设计、测试报告模板
- 工具文档：Trae 官方文档、MkDocs 站点

### P27 高效学习方法指导

- 三先三后：先看见成果再学知识 / 先保证运行再追求高级 / 先核心闭环再特色功能
- 每周给自己定一个"可验证的小目标"；做完立即验证、记录、提交
- 止损原则：宁可小而完整、能讲清楚，不要功能很多却交不了
- 用好 AI 但守住底线：验证、修改、解释、负责

### P28 答疑与交流渠道

- 课堂答疑时间、课后辅导安排
- 在线渠道：课程群 / 答疑社区 / AI 助教
- 提交与反馈：Git 仓库、作业提交方式说明
