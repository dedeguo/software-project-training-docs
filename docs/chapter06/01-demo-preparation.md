# 6.1 准备演示：视频、脚本与环境检查

## 让观看者在 3—5 分钟内看懂项目价值

!!! quote "演示不是把功能点一遍，而是让别人理解项目解决什么问题"
    第五篇完成后，你的项目已经具备可运行、可部署的 `v1.0` 版本。但如果只有代码和 README，他人需要花费大量时间才能理解项目的价值。演示视频和演示脚本的目标，是用最少的时间，让观看者快速理解：这个项目为谁解决什么问题、核心功能是什么、技术亮点在哪里、实际运行效果如何。

    本节将帮助你制作 3—5 分钟的演示视频，准备清晰的演示脚本，并确保演示环境稳定可靠。

!!! tip "本节学习目标"
    制作 3—5 分钟演示视频，清晰展示项目定位、核心功能和技术亮点；准备演示脚本，明确先说什么、后说什么、重点强调什么；完成演示环境检查，确保演示过程稳定可靠。

## 一、演示视频的结构：3—5 分钟讲清项目价值

演示视频不是功能罗列，而是**用最少的时间，让观看者理解项目解决什么问题、谁在用、怎么用、效果如何**。

### 1. 推荐的时间分配

| 时间 | 内容 | 目的 | 示例 |
| :--- | :--- | :--- | :--- |
| 0—10s | 项目定位 | 让观看者快速理解项目价值 | “这是一个校园失物招领平台，帮助失主和拾到者高效匹配” |
| 10—70s | 核心功能 | 展示主要业务流程和关键界面 | 登录 → 发布失物 → 搜索 → 认领申请 → 管理员审核 |
| 70—90s | 技术亮点 | 体现技术深度和解决问题的能力 | JWT 鉴权、角色权限、Docker 部署、测试覆盖 |
| 90—100s | 部署访问 | 证明项目可复现、可运行 | 展示 Docker 部署状态、访问地址、核心流程 |

### 2. 项目定位：一句话说明价值

**避免：**

```text
这是一个使用 Spring Boot 和 Vue 开发的管理系统。
```

**推荐：**

```text
这是一个校园失物招领平台，解决失物信息分散、认领过程难追踪、虚假认领难审核的问题，帮助校园用户完成可验证的失物归还流程。
```

关键要素：

- **为谁**：目标用户（失主、拾到者、管理员）；
- **解决什么问题**：具体痛点（信息分散、难追踪、难审核）；
- **带来什么价值**：可验证的失物归还流程。

### 3. 核心功能：按业务流程展示

不要逐个菜单点击，而是按**核心业务流程**展示：

```text
用户 A 登录
→ 发布失物信息
→ 用户 B 搜索并找到
→ 用户 B 提交认领申请
→ 管理员审核
→ 用户 A 确认归还
```

每个步骤展示关键界面和操作，避免无关的页面跳转。

### 4. 技术亮点：突出解决问题的能力

技术亮点不是罗列技术栈，而是**说明你用技术解决了什么问题**：

| 技术亮点 | 解决的问题 | 展示方式 |
| :--- | :--- | :--- |
| JWT 鉴权 | 确保用户身份安全，防止未授权访问 | 展示登录、权限拦截、角色差异 |
| 角色权限控制 | 确保不同角色只能访问自己的功能 | 展示普通用户和管理员的不同界面 |
| Docker 部署 | 确保项目可复现、可一键启动 | 展示 `docker-compose up` 和访问效果 |
| 测试覆盖 | 确保核心流程正确、缺陷已修复 | 展示测试报告和关键测试用例 |

### 5. 部署访问：证明项目可运行

最后 10 秒展示：

- Docker 容器运行状态（`docker compose ps`）；
- 浏览器访问地址（`http://localhost:8088`）；
- 核心流程的实际运行效果（登录 → 操作 → 结果）。

## 二、演示脚本：让演示过程清晰可控

演示脚本不是逐字稿，而是**演示过程的路线图**，帮助你控制节奏、突出重点、避免遗漏。

### 1. 演示脚本的基本结构

```markdown
# 【项目名称】演示脚本

## 1. 项目定位（10s）
- 口播：这是一个【项目类型】，解决【什么问题】，帮助【目标用户】完成【什么任务】。
- 画面：项目首页或 Logo。

## 2. 核心功能（60s）
- 口播：下面展示核心业务流程。
- 画面：登录 → 功能 1 → 功能 2 → 功能 3。
- 重点：每个功能用一句话说明价值。

## 3. 技术亮点（20s）
- 口播：项目使用了【关键技术】，解决了【什么问题】。
- 画面：架构图、关键代码、测试报告。

## 4. 部署访问（10s）
- 口播：项目已通过 Docker 部署，可一键启动。
- 画面：Docker 状态、访问地址、核心流程。
```

### 2. 演示脚本示例

```markdown
# 校园失物招领平台演示脚本

## 1. 项目定位（10s）
- 口播：这是一个校园失物招领平台，解决失物信息分散、认领过程难追踪的问题，帮助失主和拾到者高效匹配。
- 画面：项目首页，展示平台名称和核心功能入口。

## 2. 核心功能（60s）
- 口播：下面展示失物发布和认领的完整流程。
- 画面：
  - 用户 A 登录，发布失物信息（10s）；
  - 用户 B 登录，搜索失物并提交认领申请（20s）；
  - 管理员登录，审核认领申请（15s）；
  - 用户 A 确认归还，流程完成（15s）。
- 重点：每个步骤用一句话说明价值，例如“用户 B 可以通过关键词搜索快速找到失物”。

## 3. 技术亮点（20s）
- 口播：项目使用 JWT 鉴权和角色权限控制，确保数据安全；使用 Docker Compose 实现一键部署。
- 画面：
  - 展示 JWT 鉴权流程（10s）；
  - 展示 Docker 部署状态（10s）。

## 4. 部署访问（10s）
- 口播：项目已通过 Docker 部署，访问地址为 http://localhost:8088。
- 画面：Docker 容器状态、浏览器访问、核心流程运行。
```

### 3. 演示脚本的注意事项

- **先说什么**：项目定位，让观看者快速理解价值；
- **后说什么**：核心功能，按业务流程顺序展示；
- **重点强调**：技术亮点和解决的问题；
- **避免什么**：逐个菜单点击、无目的的页面跳转、解释每个按钮的作用。

## 三、核心流程截图：让成果可视化

核心流程截图是演示视频的补充，也是 README、答辩 PPT 和作品集的重要素材。

### 1. 推荐的截图清单

| 截图 | 说明 | 用途 |
| :--- | :--- | :--- |
| 项目首页 | 项目定位和核心功能入口 | README、演示视频、答辩 PPT |
| 登录页 | 用户认证和角色选择 | 演示视频、答辩 PPT |
| 核心功能页 1 | 主要业务操作界面 | README、演示视频、答辩 PPT |
| 核心功能页 2 | 关键业务流程界面 | 演示视频、答辩 PPT |
| 管理界面 | 管理员视角和权限差异 | 答辩 PPT、个人贡献说明 |
| 部署状态 | Docker 容器运行状态 | README、答辩 PPT |
| 测试报告 | 测试覆盖和缺陷修复情况 | 答辩 PPT、个人贡献说明 |

### 2. 截图的规范

- **分辨率**：建议 1920×1080，确保关键内容可读；
- **浏览器**：使用 Chrome 或 Edge，清理缓存和插件；
- **数据**：使用测试数据，避免真实隐私信息；
- **标注**：在截图上添加箭头或文字说明，突出关键功能；
- **命名**：使用有意义的文件名，例如 `01-homepage.png`、`02-login.png`。

### 3. 截图的说明文字

每张截图下加一句说明，例如：

```markdown
![活动报名列表](docs/images/activity-list.png)

> 学生可以查看已发布活动、剩余名额和个人报名状态。
```

## 四、演示环境检查：确保演示过程稳定可靠

演示环境检查是避免演示过程中出现意外的关键步骤。

### 1. 演示环境检查清单

| 检查项 | 检查内容 | 检查方法 |
| :--- | :--- | :--- |
| 网络连接 | 网络稳定，速度足够 | 打开多个网页，测试加载速度 |
| 测试账号 | 账号可用，密码正确 | 提前登录，确认角色权限 |
| 数据库 | 数据完整，测试数据已初始化 | 执行核心流程，确认数据正确 |
| 浏览器 | 无插件干扰，缓存已清理 | 使用无痕模式或清理缓存 |
| 屏幕分辨率 | 适合演示，关键内容可读 | 调整分辨率，测试显示效果 |
| 字体大小 | 适中，关键内容可读 | 调整浏览器缩放比例 |
| 备份方案 | 录屏 / 本地部署 / 截图已准备 | 确认备用方案可用 |

### 2. 演示环境检查示例

```markdown
# 演示环境检查清单

- [x] 网络连接稳定，速度 100Mbps；
- [x] 测试账号 admin / admin123 可用，角色为管理员；
- [x] 数据库已初始化，包含 10 条测试数据；
- [x] 浏览器使用 Chrome 无痕模式，无插件干扰；
- [x] 屏幕分辨率 1920×1080，字体大小 100%；
- [x] 已准备录屏备用方案（OBS Studio）；
- [x] 已准备本地部署备用方案（Docker Compose）；
- [x] 已准备截图备用方案（核心流程截图 10 张）。
```

### 3. 常见演示环境问题与解决方案

| 问题 | 原因 | 解决方案 |
| :--- | :--- | :--- |
| 网络中断 | 在线部署依赖网络 | 使用本地部署或录屏备用方案 |
| 账号失效 | 测试账号被锁定或密码错误 | 提前确认账号，准备多个测试账号 |
| 数据库异常 | 数据被修改或删除 | 提前备份数据库，准备恢复脚本 |
| 浏览器卡顿 | 插件过多或缓存过多 | 使用无痕模式，清理缓存 |
| 分辨率不适 | 投影或屏幕分辨率不匹配 | 提前测试，调整分辨率 |

## 五、备用演示方案：应对突发情况

演示过程中可能出现网络中断、账号失效、数据库异常等突发情况。准备备用演示方案，可以确保演示顺利进行。

### 1. 备用演示方案的类型

| 方案 | 适用场景 | 准备方法 |
| :--- | :--- | :--- |
| 录屏 | 网络中断、部署失败 | 提前录制完整演示视频 |
| 本地部署 | 在线部署不可用 | 使用 Docker Compose 本地启动 |
| 截图 | 无法实时演示 | 准备核心流程截图，配合口播讲解 |
| PPT 演示 | 所有技术方案失败 | 使用 PPT 展示项目定位、功能和成果 |

### 2. 备用演示方案的准备

```markdown
# 备用演示方案

## 方案 1：录屏
- 工具：OBS Studio / Camtasia；
- 内容：完整演示视频（3—5 分钟）；
- 存储：本地 MP4 文件 + 云盘备份；
- 测试：确认视频可播放，声音清晰。

## 方案 2：本地部署
- 工具：Docker Compose；
- 命令：`docker compose up -d`；
- 访问：http://localhost:8088；
- 测试：确认核心流程可运行。

## 方案 3：截图
- 内容：核心流程截图 10 张；
- 存储：本地 PNG 文件 + 云盘备份；
- 说明：每张截图配一句说明文字。

## 方案 4：PPT 演示
- 内容：项目定位、核心功能、技术亮点、部署成果；
- 页数：10—15 页；
- 测试：确认 PPT 可正常播放。
```
