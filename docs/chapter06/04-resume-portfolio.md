# 6.4 整理简历：项目描述与面试表达

## 让课程项目成为求职或毕业设计的有效资产

!!! quote "简历项目不是罗列功能，而是证明你能用技术解决真实问题"
    6.3 完成个人贡献说明后，你已经知道自己做了什么。但简历和面试需要更进一步：用简练的语言，在 2—3 条项目描述中展示技术能力、解决问题能力和成果验证能力。

    本节将帮助你将项目成果转化为简历项目描述、作品集链接和面试表达，确保成果可复用于求职、毕业设计或继续学习。

!!! tip "本节学习目标"
    编写 2—3 条简历项目描述，使用 STAR 法则；整理作品集链接清单，包含 GitHub、演示视频和文档；准备 30 秒、2 分钟和 5 分钟三个版本的面试表达；列出 10—15 个常见面试问题与回答要点。

## 一、简历项目描述：用 STAR 法则展示能力

### 1. STAR 法则

STAR 法则是结构化回答面试问题的方法，也适用于简历项目描述。

| 要素 | 含义 | 示例 |
| :--- | :--- | :--- |
| Situation（背景） | 项目背景、解决的问题 | 校园失物信息分散，认领过程难追踪 |
| Task（任务） | 你的职责、目标 | 负责后端开发，实现用户认证和失物管理 |
| Action（行动） | 你做了什么、怎么做的 | 设计 JWT 鉴权和角色权限控制，编写 15 个测试用例 |
| Result（结果） | 成果、量化指标 | 3 个 P0 缺陷全部修复，Docker 一键部署成功 |

### 2. 简历项目描述的结构

```text
项目名称：一句话说明项目定位
→ 解决的问题：为谁解决什么问题
→ 技术栈：使用的关键技术
→ 我的贡献：具体负责的模块、关键决策
→ 量化成果：可验证的结果
```

### 3. 简历项目描述的写法

**避免（太模糊）：**

```text
负责 XX 模块开发，使用 Spring Boot 和 Vue 实现。
```

**避免（太夸张）：**

```text
独立设计并开发了千万级并发的校园失物招领平台，支持 10 万用户同时在线。
```

**推荐（具体、可验证）：**

```text
项目名称：校园失物招领平台
项目描述：为校园失物信息分散、认领过程难追踪的问题，设计并开发了支持失主、
拾到者和管理员多角色协作的失物招领平台。

技术栈：Spring Boot 3、MyBatis-Plus、Vue 3、Pinia、MySQL 8、Docker Compose、Nginx

个人贡献：
1. 设计并实现用户认证模块，通过 JWT 鉴权和角色权限控制，确保用户身份安全和数据隔离；
2. 开发失物管理和认领审核模块，支持发布、搜索、认领、审核、归还全流程；
3. 编写 15 个测试用例，覆盖正常、异常和权限场景，发现并修复 3 个 P0 缺陷；
4. 使用 Docker Compose 实现 MySQL、后端、前端、Nginx 一键部署，支持本机和局域网访问。
```

### 4. 简历项目描述的注意事项

- **真实**：技术栈、职责和成果必须与实际项目一致；
- **具体**：用具体模块、具体技术、具体数据代替模糊描述；
- **量化**：用数字说明成果（如测试用例数量、缺陷修复数量）；
- **简洁**：每条描述 1—2 行，避免大段文字；
- **可验证**：提供 GitHub 仓库、演示视频或文档链接。

## 二、作品集：让成果可访问

作品集是简历项目的延伸，让招聘者或教师能够实际查看你的项目。

### 1. 作品集的组成

| 要素 | 内容 | 作用 |
| :--- | :--- | :--- |
| GitHub/Gitee 仓库 | 项目源代码、README、文档 | 运行入口，证明代码真实 |
| 演示视频 | 3—5 分钟项目演示 | 观看入口，快速了解项目 |
| 部署地址 | 本机或在线访问地址 | 体验入口，实际使用项目 |
| 设计文档 | 需求分析、系统设计 | 思考入口，理解架构决策 |
| 测试报告 | 测试用例、缺陷修复 | 质量入口，证明项目可靠 |

### 2. 作品集链接清单示例

```markdown
# 作品集链接清单

## 1. 项目仓库
- GitHub：https://github.com/你的用户名/项目名
- Gitee：https://gitee.com/你的用户名/项目名
- 说明：包含完整源代码、README、文档和 SQL 脚本

## 2. 演示视频
- B 站：https://www.bilibili.com/video/BVXXXXXXXX
- 说明：3—5 分钟演示，包含项目定位、核心功能、技术亮点和部署访问

## 3. 部署地址（可选）
- 访问地址：http://你的域名或IP:8088
- 测试账号：admin / admin123
- 说明：Docker 部署，支持本机和局域网访问
- 注意：如部署在个人电脑，可能不长期可用

## 4. 设计文档
- 需求分析说明书：仓库 docs/01-需求分析说明书.md
- 系统设计说明书：仓库 docs/02-系统设计说明书.md
- 测试报告：仓库 docs/03-测试报告.md
- 部署说明：仓库 docs/04-部署说明.md

## 5. 技术亮点
1. JWT 鉴权 + 角色权限控制：确保用户身份安全和数据隔离
2. 统一异常处理：规范错误响应，便于前端处理
3. Docker 一键部署：降低部署门槛，确保可复现
4. 测试覆盖：15 个测试用例，覆盖正常、异常、权限场景
```

### 3. 作品集的注意事项

- **可访问**：确保链接可访问，不要使用需要登录或权限的链接；
- **可运行**：确保 README 中的启动步骤有效，招聘者可以尝试运行；
- **可验证**：确保测试报告和演示视频与实际项目一致；
- **可维护**：定期更新链接，避免链接失效。

## 三、面试表达：30 秒、2 分钟、5 分钟

面试中，你可能被要求用不同时间长度介绍项目。提前准备三个版本，可以应对不同场景。

### 1. 30 秒电梯陈述

**场景**：面试官问“简单介绍一下你的项目”，时间有限。

```text
我开发了一个校园失物招领平台，解决失物信息分散、认领过程难追踪的问题。
我负责后端开发，使用 Spring Boot 和 MyBatis-Plus，通过 JWT 鉴权和角色权限控制确保数据安全，
使用 Docker Compose 实现一键部署。项目已通过 15 个测试用例验证，3 个 P0 缺陷全部修复。
```

关键要素：

- 项目定位（一句话）；
- 我的职责（一句话）；
- 技术栈（一句话）；
- 量化成果（一句话）。

### 2. 2 分钟项目介绍

**场景**：面试官问“详细介绍一下你的项目”，时间较充裕。

```text
我开发了一个校园失物招领平台，解决校园失物信息分散、认领过程难追踪、虚假认领难审核的问题。

项目支持三类角色：失主、拾到者和管理员。核心功能包括失物发布、关键词搜索、认领申请、
管理员审核和归还确认。业务规则包括：同一用户不能重复认领、认领需管理员审核、归还后状态不可修改。

我负责后端开发，使用 Spring Boot 3 和 MyBatis-Plus，设计并实现了 JWT 鉴权和角色权限控制，
确保用户身份安全和数据隔离。数据库设计包含用户、失物、认领、审核四张核心表，通过外键关联确保数据一致性。

测试方面，我编写了 15 个测试用例，覆盖正常、异常和权限场景，发现并修复 3 个 P0 缺陷。
部署方面，我使用 Docker Compose 实现 MySQL、后端、前端、Nginx 一键部署，已在本地环境完成核心流程验证。

项目代码在 GitHub，有完整的 README、设计文档和测试报告。
```

关键要素：

- 项目背景和解决的问题；
- 核心功能和业务规则；
- 我的职责和技术栈；
- 测试验证和部署成果；
- 项目链接和文档。

### 3. 5 分钟深入讨论

**场景**：面试官问“深入讲讲你的项目，特别是技术决策和难点解决”。

```text
【项目背景 30s】
我开发了一个校园失物招领平台，解决校园失物信息分散、认领过程难追踪、虚假认领难审核的问题。

【需求分析 60s】
项目支持三类角色：失主、拾到者和管理员。核心功能包括失物发布、关键词搜索、认领申请、
管理员审核和归还确认。业务规则包括：同一用户不能重复认领、认领需管理员审核、归还后状态不可修改。

【技术选型 60s】
后端选择 Spring Boot 3 和 MyBatis-Plus，原因是生态成熟、适合企业级应用、团队有 Java 基础。
前端选择 Vue 3 和 Pinia，原因是学习曲线平缓、组合式 API 便于代码组织。
数据库选择 MySQL 8，原因是开源免费、社区活跃、适合中小型项目。
部署选择 Docker Compose，原因是降低部署门槛、确保可复现。

【架构设计 60s】
采用前后端分离架构，前端通过 Nginx 代理 /api 访问后端。后端分为 controller、service、dao 三层，
通过 DTO 和 VO 隔离内部模型和外部接口。鉴权使用 JWT + 拦截器，通过注解控制角色权限。
数据库设计包含用户、失物、认领、审核四张核心表，通过外键关联确保数据一致性。

【难点解决 60s】
遇到三个主要问题：
1. 重复认领：服务层未判断用户是否已有认领记录，通过新增唯一查询和业务异常解决。
2. 权限绕过：删除接口未校验用户角色，通过新增角色权限注解和拦截器校验解决。
3. Docker 部署：后端容器连不上数据库，通过将 DB_HOST 从 localhost 改为服务名 mysql 解决。

【测试验证 30s】
编写 15 个测试用例，覆盖正常、异常和权限场景，发现并修复 3 个 P0 缺陷，全部回归通过。
在 Docker 环境完成核心流程验证，系统运行稳定。

【总结 30s】
通过这个项目，我掌握了 Spring Boot 和 Vue 的全栈开发能力，学会了 Docker 容器化部署，
理解了测试驱动开发的重要性。项目代码在 GitHub，有完整的文档和测试报告。
```

## 四、常见面试问题与回答要点

### 1. 技术类问题

| 问题 | 回答要点 |
| :--- | :--- |
| 为什么选择 Spring Boot？ | 生态成熟、依赖注入、AOP、自动配置 |
| JWT 和 Session 的区别？ | 无状态、可扩展、适合前后端分离 |
| MyBatis-Plus 的优势？ | 代码生成、分页插件、乐观锁、逻辑删除 |
| Docker 的优势？ | 环境隔离、可复现、快速部署 |
| Vue 3 的组合式 API 有什么优势？ | 逻辑复用、类型推导、代码组织 |

### 2. 项目类问题

| 问题 | 回答要点 |
| :--- | :--- |
| 项目最大的难点是什么？ | 具体问题、根因分析、解决过程、验证结果 |
| 你在项目中负责什么？ | 具体模块、关键决策、量化成果 |
| 项目的测试覆盖率是多少？ | 核心功能 100%、异常 80%、权限 100% |
| 项目部署在哪里？ | Docker 本地部署、局域网访问、可复现 |
| 项目有多少用户？ | 课程项目，测试数据 10 条，未上线 |

### 3. 个人类问题

| 问题 | 回答要点 |
| :--- | :--- |
| 你从这个项目中学到了什么？ | 技术能力、工程能力、协作能力、反思能力 |
| 你觉得项目有什么不足？ | 诚实承认、说明原因、后续改进计划 |
| 如果重新做，会怎么改进？ | 测试驱动开发、CI/CD、监控日志 |
| 你如何学习新技术？ | 官方文档、视频教程、实践项目、社区交流 |
| 你的职业规划是什么？ | 短期目标、中期目标、长期目标 |

## 五、面试表达的注意事项

### 1. 回答技巧

- **STAR 法则**：用背景 → 任务 → 行动 → 结果组织回答；
- **具体而非模糊**：用具体例子代替空泛描述；
- **量化而非定性**：用数字说明成果；
- **诚实而非虚构**：不知道的问题诚实说明；
- **简洁而非冗长**：控制回答时间，突出重点。

### 2. 常见错误

| 错误 | 正确做法 |
| :--- | :--- |
| 夸大技术栈 | 只写实际使用的技术 |
| 虚构职责 | 明确个人贡献和团队贡献 |
| 抄袭简历 | 基于真实项目经历编写 |
| 无证据支持 | 提供 GitHub 仓库、演示视频 |
| 回答过长 | 控制时间，突出重点 |

### 3. 面试前的准备

- [ ] 简历项目描述已更新，使用 STAR 法则；
- [ ] 作品集链接已验证可访问；
- [ ] 30 秒、2 分钟、5 分钟三个版本的面试表达已练习；
- [ ] 10—15 个常见面试问题已准备回答要点；
- [ ] 已准备现场演示方案（如需要）；
- [ ] 已准备备用方案（如网络中断）。
